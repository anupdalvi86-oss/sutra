Updated: 2026-09-30

## What works

- Supabase is the authoritative company state store. Database functions gate assignments, approvals, budget reservations and settlement, standing code authority, QA/Security evidence, merges, legal escalations, and audit records. Direct client roles cannot read the private operational tables.
- Telegram accepts founder commands only from ID `8776723105`. CEO and department status commands produce board-style, two-part reports with projects, objectives, task queues, completed work, blockers, pending approvals, legal escalations, budgets, held reservations, and relevant customer/campaign records. Data-source failures are reported as partial rather than hiding healthy sections.
- Railway runs private `sutra-api` and Hermes (`sutra`) services. Merge commit `3b978cf` deployed `sutra-api` successfully; Hermes skipped redeployment because its watched paths were unchanged. Both endpoints remain private.
- The deployed workflow supports proposal intake, parallel CPO/CTO review, CFO estimate and PM plan, metered role artifacts, GitHub issue/branch/PR execution, CI evidence polling, QA and Security handoffs, and a separate exact-head release worker. The worker can merge only when the standing founder repository grant, project/task scope, CI, QA and Security evidence all pass.
- Spending controls use configurable Supabase policies and a shared all-in EUR initiative ledger. Reservations, actuals and unresolved usage are preserved. The live policy includes an €8 monthly AI-inference hard stop. On 2026-09-30 the founder set this initiative's all-in ceiling to €17.60 (USD $20 converted conservatively at the ECB 2026-09-29 reference rate). The evidence-backed fallback assessment estimates €15.97 all-in, leaving €1.63 under the cap; confidence is medium because the Railway account tier and actual usage were not visible.
- The private customer-email outbox enforces consent, unsubscribe, task assignment, assessed initiative budget, project legal holds and legal escalations. PR #221 also lets assigned Sales/Marketing task artifacts request up to five messages to customer IDs named in the task; a database trigger sends each request through the same cost-ceiling and shared-ledger authorization RPC. Disallowed actions are safely recorded as blocked while the internal artifact completes. The opt-in Resend worker uses atomic leases and a pre-send authorization recheck; ambiguous outcomes are terminal and retain unknown reservations. A founder-only audited database setting defines the maximum reserved cost per message. It is intentionally unset in production, and the worker remains disabled; no customer messages have been sent.
- PR #221 persists CMO campaign plans as private, task-linked campaign records with channel, estimate, and budget-fit state. The campaign-email guard enforces its cap across reserved, actual and unknown costs at enqueue and immediately before delivery; successful sends mark the campaign active. CEO/CMO status includes bounded delivery counts and separate reserved, unknown and actual email spend, without customer addresses or message content. Over-cap or legally blocked drafts are marked `approval_required` and audit logged. No ad-platform publishing or ad-buy integration exists.
- Founder code authority is an audited database grant for this repository, with bounded task/branch/PR/merge/QA/Security/deploy capabilities. It does not increase budgets or spending authority. Exhausted task #107 was not retried.
